# Platform behaviour audit 2026-10-21

A user on Android 16 (HyperOS 3) crashed on every start after "Check for updates > Yes": the daily-check job asked JobScheduler for a network constraint without `ACCESS_NETWORK_STATE`, which apps targeting Android 14+ may not do (`SecurityException`; fixed in commit 17009a4). The earlier caveat sweeps followed the streaming and radio pipeline. This audit goes through the Android behaviour-change pages for Android 10 to 17 (all apps and per target SDK), the foreground-service, notification, PendingIntent, receiver, package-visibility, storage, Bluetooth and background-start pages, and every call site in `app/src/main`, `src/github`, `src/fdroid`, `src/debug` and the manifests. Sources: developer.android.com `about/versions/{10..17}/behavior-changes-*`, `develop/background-work/services/fgs/{service-types,restrictions-bg-start}`, the `android-36` platform annotations (to see what lint can know), and the vendor background pages for the OEM table.


**Result: 3 bugs fixed on the branch (B1 to B3), 1 bug proposed (P1), 18 checks on a phone, 53 rules safe (32 with a guard, 21 with no call site), 1 earlier fix (F0). Lint found 1 of the 4 bugs outright (B3) and warned about a second (B1).**

## Rules checked and found safe (53)

Each row names the guard. These rules have no call site in the code (checked by search): SYSTEM_ALERT_WINDOW, MediaProjection, WebView, Tiles, widgets, shortcuts, deep links, share target, NFC/USB, DownloadManager/WorkManager, exact alarms, contacts/SMS/calendar, `QUERY_ALL_PACKAGES`, `ACTION_CLOSE_SYSTEM_DIALOGS`, clipboard reads, Zip extraction, dynamic code loading (`System.load` only in the host JVM test path of `NativeOpusBridge`), `BODY_SENSORS`, `MediaStore`, `READ_MEDIA_*`/`READ_EXTERNAL_STORAGE`, `dataSync`/`mediaProcessing` services.

- **JobScheduler (14, 16).** Permission declared (`github/AndroidManifest.xml`); `schedule` guarded; work on its own thread, `jobFinished` always called with the held `JobParameters` (no `STOP_REASON_TIMEOUT_ABANDONED`, no ANR on `onStartJob`); `BIND_JOB_SERVICE` on the service. `ConnectivityManager` (`UpdateEngine.online`) needs the same permission on every release.
- **Foreground service types and permissions (14, 15).** Types `camera|microphone|connectedDevice|mediaPlayback|location` each have `FOREGROUND_SERVICE_*`. Prerequisites checked before `startForeground`: camera/microphone grants (`ServiceTypePolicy.withoutUngrantedTypes`, `ActiveVideoSessionService.kt:154`), `connectedDevice` rests on the declared `CHANGE_WIFI_STATE` (pinned by `ServiceManifestTest`), the location type only while the app is visible and Location is on. A background start is caught (`ActiveVideoSessionService.kt:340`, registry entry `bg-fgs-start-fallback`). Boot resume starts only the `connectedDevice` type (Android 15 forbids the others from `BOOT_COMPLETED`). No type has a timeout; `onTimeout` is implemented anyway.
- **Notifications (13).** `POST_NOTIFICATIONS` is requested at onboarding and before call alerts; every poster checks `areNotificationsEnabled` or the grant (`MessagingV2Notifications.kt:221`, `NameWindowRuntime.kt:252`, `StoreForwardUi.kt:94`); the session service runs without the grant. Channels are created before every `notify`. CallStyle has a foreground service or a full-screen intent (Android 12 rule). Full-screen intent: `canUseFullScreenIntent` with a settings link (Android 14, `CallFeatureSettings.kt:158-175`).
- **PendingIntent (12, 14).** All creation sites pass `FLAG_IMMUTABLE`; the one mutable intent (`UpdateEngine.kt:344`, PackageInstaller needs it) names its component and package.
- **Receivers and components (12, 14).** Every custom-action receiver passes `RECEIVER_NOT_EXPORTED`; receivers without a flag listen only to platform broadcasts. Every manifest component has an explicit `android:exported`; only `MainActivity` (and two debug receivers) are exported. Notification actions use `setPackage`. No implicit intent targets a non-exported component.
- **Bluetooth (12, 13, 16).** Legacy permissions end at API 30, location at 32, `BLUETOOTH_*` from 31 with `neverForLocation` on scan; requests are per API level (`OnboardingActivity.permissions`, `MainActivity.requiredPermissions`). `BluetoothAdapter.enable()/disable()` (always false from Android 13) is DEBUG-only (`BluetoothRestart`). The Android 16 bond-loss intents change no code path (the app never bonds).
- **Permissions and privacy.** `READ_PHONE_STATE` is not declared and the call-state read is guarded (`CallAudioFocus.kt:127`, the Android 12 rule); partial photo access does not apply (system pickers only: `PickVisualMedia`, `GetContent`, `OpenDocument`, `CreateDocument`); Wi-Fi Direct uses `NEARBY_WIFI_DEVICES` (13+) or fine location plus the Location switch (10 to 12) (`OfflineAppShareActivity.kt`); the app never toggles Wi-Fi (Android 10 rule).
- **Storage (10, 11).** Everything is app-private or `noBackupFilesDir`; sharing goes through a `FileProvider` on `cache/app-share/` with a read grant; no legacy storage flag.
- **Back, window and layout (15, 16).** Only `OnBackPressedCallback` (no `onBackPressed`, no `KEYCODE_BACK`), so predictive back on Android 16 needs no opt-out. Eight activities draw edge-to-edge with `setDecorFitsSystemWindows(false)` and a system-bar inset listener; the theme sets transparent bars. The display is read from an Activity (`CameraOrientation`, the Android 11 `Context.getDisplay` rule).
- **16 KB pages (15, 16).** Linker flags `max-page-size=16384`, ELF `p_align` 0x4000, `zipalign -c -P 16` passes on the existing release APK (checked 2026-10-21).
- **Other.** Hidden `SystemProperties` reflection is wrapped (`DeviceTraitsProbe`, `GattLinkBudget`); `String.format` strictness (15): no positional-format misuse (aapt warns once about `%` in `settings_thermal_description`, which is never formatted); background audio focus (15): requests come from a foreground service; Safer Intents (16) are not enabled; `queries` cover the intents and packages read.

## Check on a phone (18)

For the UI crawl on an Android 16 phone and on an emulator. Tap paths start at the Home tab.

1. **Update install on Android 16 (intent redirection hardening).** Settings > Features > Check for updates > Check now > choose a file (a newer MeshLive APK from the nearby-install section) > Install. The system installer dialog must open. The confirm intent is a nested `EXTRA_INTENT` launched from `UpdateInstallReceiver` (`github/UpdateReceivers.kt:25-37`) and from `UpdateActivity.onResume`; Android 16 added default launch protection for nested intents. If it does not open, `adb logcat -s PackageManager ActivityTaskManager` shows the block; the documented opt-out is `Intent.removeLaunchSecurityProtection()` on the nested intent.
2. **Check for updates, yes and no** (GitHub build): Settings > Features > Check for updates switch > Yes (or the one-time "Check for updates when online?" question) > Check now; then airplane mode and Check now again. No crash, a plain message. Repeat after Force stop and a cold start (the job is re-armed at start).
3. **Onboarding on a fresh install:** Allow permissions (Nearby devices, Camera, Microphone, Notifications) > Not now/Allow on the background page > Start. Check insets (buttons not under the navigation bar) and the Back gesture on each page.
4. **Permission denied for good:** deny Camera twice, then Home readiness card > Open settings; the app settings page must open.
5. **QR scanner:** People > Meet/Verify > Scan. Camera prompt, preview, status text above the navigation bar (zxing `CaptureActivity` has no insets handling and its own theme; Android 15 edge-to-edge applies), rotation on a tablet emulator.
6. **Show code and screenshots:** Verify > Show my code (FLAG_SECURE: a screenshot must be blocked).
7. **Export diagnostics and crash prompt:** Help and feedback > Export diagnostics (clipboard toast plus chooser). After a forced crash, the next start shows "Share a crash report?"; Share opens MainActivity and then the chooser.
8. **Share the app:** Help and feedback > Share this app (chooser with the APK) and Share app nearby (Wi-Fi Direct; switch it on under Settings > Features first; Android 12: Location permission and Location switch screens; Android 13+: Nearby devices; the Wi-Fi panel on 10+). On Android 16 with `RESTRICT_LOCAL_NETWORK` enabled (`adb shell am compat enable RESTRICT_LOCAL_NETWORK io.github.meshlive.app`, reboot) the receiving phone must still reach the sender's page.
9. **Call alerts on a locked phone:** Settings > Features > Calls > lock-screen alert on > "Allow full-screen intents" link (Android 14+); lock the phone, receive a call.
10. **Emergency wipe:** Settings > Triple-tap to wipe on > triple-tap the Home title > countdown > wipe; the app restarts at onboarding.
11. **Boot resume (debug only today):** no user switch exists yet (`BootResume.setEnabled` has no caller); with a debug build and `test_boot_resume=true`, reboot: the connectedDevice notification returns; on Xiaomi/HyperOS Autostart must be on.
12. **Battery exemption:** onboarding background page and the Settings reliability card fix button: the system prompt for `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS` opens (absent on some Go and Huawei builds; the list screen is the fallback).
13. **Go live / Call with the microphone or camera denied** (Android 14+): the session service must refuse the type with a notice, not close the app.
14. **Large screen:** Pixel Tablet or foldable emulator (API 36): rotate in Home, Verify and Settings; the window must stay a portrait letterbox (B1).
15. **Messages (experimental, Settings > Features > Messages (store-and-forward / Messaging v2 switches)):** record a voice note (microphone prompt), pick a photo and a file, Open and Save a received file (`MessagingV2OpenProvider` grants).
16. **Back gesture inside the app (predictive back):** Settings sub-pages, a message thread, the audio-live screen, Verify; each must step back one level, not leave the app.
17. **Android 10 and 11, Settings cards:** the Settings page cards use the Android 12 attribute `clipToOutline` in a style (`themes.xml:349`, lint NewApi); older releases ignore it, so check that rounded card corners and their content look right on an API 29 and an API 30 phone (cosmetic).
18. **Share app nearby on Android 12 / 12L (B3):** switch it on under Settings > Features, open Help > Share app nearby: one Location dialog with Precise and Approximate must appear; Precise starts sharing, Approximate shows the permission message.

## Permanent guard and what lint cannot see

`PlatformBehaviourGuardTest` (JVM, reads the manifests and sources) fails the build when: a network-constrained job or `ConnectivityManager` use lacks `ACCESS_NETWORK_STATE` in that flavour's merged manifest (lint cannot: the `android-36` platform annotations carry no `@RequiresPermission` for `JobInfo.Builder.setRequiredNetworkType`); a job service lacks `BIND_JOB_SERVICE`; a component lacks `android:exported` or an unexpected one is exported; a foreground-service type lacks its `FOREGROUND_SERVICE_*` permission; a `registerReceiver` has neither an export flag nor a place in the platform-broadcast allowlist; a `PendingIntent` has no mutability flag, or a mutable one is implicit; `notify`/`setFullScreenIntent` without the permission (and without the Android 14 check); exact alarms without the permission and check; package-installer code in the shared source set; the boot receiver starting a camera/microphone service; `onBackPressed`/`KEYCODE_BACK` (Android 16); the large-screen opt-out missing or targetSdk raised to 37; the exclude-all backup rules missing; the 16 KB linker flag missing. A new exception goes into an allowlist in that file with its reason.

## Lint (`:app:lintGithubDebug`, 2026-10-21)

19 errors and 684 warnings; the task fails on any build of this tree (there is no baseline and lint is not part of the routine checks). Every error was triaged:

| Lint ID | Count | Verdict |
| --- | --- | --- |
| `CoarseFineLocation` | 1 | Real: B3 (fixed). |
| `MissingPermission` | 9 | Accepted. Bluetooth calls inside lambdas of `AdaptivePhy`, `BleL2capControl`, `ReachAdvertiser` that the function-level `@SuppressLint` does not reach; most are inside `runCatching`, and revoking a runtime permission kills the process. |
| `NewApi` / `InlinedApi` (`CameraVideoEncoder`, 3 errors) | 3 | Low. `SCALER_ROTATE_AND_CROP` keys are public from API 31 but guarded from 30; the reads sit in `safeCameraRead` (catches `Throwable`, including `NoSuchFieldError`) and the writes behind the experimental switch `rotateAndCropNone` (V-23, off). No change; use `>= S` if the experiment is ever promoted. |
| `NewApi` (`themes.xml:349`) | 1 | Cosmetic: `clipToOutline` in a style is ignored before API 31 (check item 17). |
| `WrongConstant` | 2 | False positives: the write result is compared with 0 (equal to `BluetoothStatusCodes.SUCCESS`); `MediaExtractor` sample flags are copied into `BufferInfo.flags`, the documented idiom (bits 1 and 8 line up; the encrypted bit is not used). |
| `StringFormatInvalid` | 2 | Harmless: `contact_scan_again_text` takes an unused argument; `experimental_relayed_calls_description` has "20% battery" and is read with `getString(id)` (no formatting). |
| `ForegroundServiceType` | 1 | False positive: the manifest declares the types; lint cannot resolve `this` inside the `ForegroundStartSequence` lambda. |

Warnings worth knowing: `DiscouragedApi` on every `screenOrientation="portrait"` (Android 16 ignores it on large screens: B1), `LockedOrientationActivity`, `DataExtractionRules` (asks for `fullBackupContent` for API 29 to 31; moot because `allowBackup="false"`), `BatteryLife` (Play policy for `REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`, already noted in the manifest), `UnspecifiedRegisterReceiverFlag` (the platform-broadcast fallback branch in `BleCocClient`), `ExportedReceiver` (debug receiver), `PrivateApi` (guarded `SystemProperties` reflection), `UnsafeDynamicallyLoadedCode` (host test path), `ChromeOsAbiSupport` (arm64 only).

What lint would and would not have caught: it flags the missing coarse location (B3) and warns about locked orientation (B1). It cannot catch the original crash (F0) because the platform annotations carry no `@RequiresPermission` on `JobInfo.Builder.setRequiredNetworkType` (checked in `platforms/android-36/data/annotations.zip`), cannot see device-to-device transfer rules (B2 beyond a missing-attribute warning), runtime rules such as foreground-service start restrictions, intent-redirection or the exported-activity extras crash (P1). `PlatformBehaviourGuardTest` covers the manifest-and-source facts lint cannot.
