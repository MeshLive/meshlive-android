# Design RT: relay child thinning (per-child frame-rate selection at a relay)

Default off (`test_relay_child_thinning`, DEBUG launch extra; Experimental). No wire change: nothing in BMH2/BMH3, BMS1, BME1, BTV3, BFG1 or the mesh envelope changes (PROTOCOL needs no edit). It is phase 2 (P2) of the adaptive-scaling review (`adaptive-scaling-svc.md`, 2026-10-13), which proposed promoting the temporal-layer experiment into per-child selection at relays, as SFUs do.

**Problem.** A relay forwards the source's records to each direct child unchanged. With one slow child there were only bad answers: forward everything and let the child's queue age, shed to keyframes (the keyframe is the largest frame, so a starved link loops), or withdraw the child so it reroutes to the source. A relay S24 -> ASUS -> A15s starved the A15s (the ASUS -> A15s GATT link carried about 44-88 kbps) at 0.1-0.2 FPS while the ASUS itself was fine. The relay can drop frames that the child can do without instead of letting the whole stream fail.

**What the reference stacks do.** mediasoup VP9 (`worker/src/RTC/RTP/Codecs/VP9.cpp`, ProcessRtpPacket) keeps a target and a current temporal layer per consumer, drops packets above the current layer, rewrites picture IDs, and moves up a temporal layer only at a switching-up point; it never needs a keyframe for a temporal change but does for a spatial up-switch. LiveKit's dependency-descriptor selector forwards by decode target and re-checks chain integrity. Both are per-receiver filters keyed on in-band layer data, the same shape as a hop-local relay. MeshLive uses the mesh flags it already has: a frame is a droppable enhancement only when its own bitstream proves that nothing references it (`BitstreamDroppability`), which is stronger than trusting an encoder's layer id; the proof is the reason it needs no switching-up-point bookkeeping (a discardable frame is never a reference, so any layer step is safe).

**Levels per direct child.**

| Level | Forwarded to this child | Child sees | Needs a keyframe to enter / leave |
| --- | --- | --- | --- |
| full | everything | the source's frame rate | no / no |
| base | everything except verified-discardable video | half the frame rate (layer 0 of two) | no / no |
| audio | audio, codec configuration, rotation, lifecycle records; no video | frozen last frame, "Video paused: weak link", speech continues | no / **yes** (requested with the bounded-age back-off, 1.5 s doubling to 15 s) |

Quarter rate needs three temporal layers (`android.generic.3` / L1T3) and a way for a relay to tell layer 1 from layer 2. That is a new flag bit or a new layer field, so it is a wire change, and it is left as a follow-up behind the same switch. With two layers, base is half rate.

**Policy (`RelayChildLayerPolicy`, constants in `Config`, unit-tested).** Evidence is this relay's queue for the child (age of the oldest queued record), what this relay delivered to that child's link (bytes handed over, over 3 s), the link's capacity measured only while media waited (a drained queue says nothing about capacity), the child's own late-media heartbeat flag, and bounded-age shed events. Nothing from beyond the next hop is used (hop-local rule).

- Down: a queue 2 s old, or a shed, acts at once. Otherwise "behind" (600 ms; 300 ms when the child reports late media) for 1 s steps full -> base, and for 1.8 s (after a 2.5 s settle) base -> audio. A keyframe that just left the queue is excused (its airtime, not a steady backlog) until 2 s. With a fresh capacity measurement below 75% of the base layer's offered rate, full goes straight to audio. A stream with no layer goes full -> audio after the longer hold; a stream with no audio never goes to audio (the withdrawal rules decide, as before).
- Up: one level at a time, after the level has been held at least `upHold` (8 s), the queue has been calm (under 150 ms, child not late) for 4 s, and the measured capacity (if fresh) covers the next level by 15% and, from audio, the keyframe's airtime is under 4.5 s. A step down within 20 s of a probe doubles `upHold` (to 60 s); a probed level that then holds 30 s resets it.
- The existing withdrawal and re-anchor rules stay as the last resort; the policy acts earlier (2 s against their 2.5 s sustained).

**Dropping is end-to-end safe.** Whole records only. Each record carries its own content sequence in a sealed header (flags included in the AEAD associated data); the opener requires `sequence >= next`, so a gap is accepted while replay and reordering fail; the mesh layer requires a strictly increasing envelope sequence. This is the same property bounded media age and `THINNED` already rely on. The viewer's decoder queue does not count sequence gaps. Tests seal a real stream, thin it at each level, and open it with the real opener: the child's flags equal the sealed flags, the gap is accepted, a replay is refused, a record with a cleared flag bit is refused, and a reference-chain model decoder decodes every frame it receives at base, after returning to full, and after an audio pause followed by a keyframe. A hostile relay could always drop records; a hostile source could mislabel a reference frame discardable, but the source is the authenticated stream owner and verifies droppability from the bitstream before marking.

**Source side.** With the switch on the encoder runs the temporal-layer experiment: native libaom always (alternating explicit references), MediaCodec AV1 with `KEY_TEMPORAL_LAYERING=android.generic.2`, MediaCodec VP9 only with `test_hardware_temporal_layers` (error-resilient layered VP9 cost about 11 VMAF on the M31 OMX encoder, which remains the default reason not to ask for it). If an encoder rejects the schema it falls back to single layer; if it accepts it but a frame's bitstream does not prove droppability, that frame is not marked, so a relay sees no base layer and the policy goes straight from full to audio. `BENCHMARK temporal_layering` records requested and reported schema per phone. Layering stays on for the whole stream (the source cannot see a weak link two hops away), so the stream pays about 2.5 VMAF while the switch is on; A/B against off.

**Child side (no new record).** The pause is inferred, not signalled: audio keeps arriving, the source has not paused or turned its camera off (stream-state records), and no video record has arrived for 3 s. One video record clears it. That avoids a new relay-to-child record and the version skew an unknown record would cause on an older phone; the cost is that any 3-second video gap with audio running reads "weak link" while the switch is on (including a keyframe still in flight on a very slow link, which is a weak link). A hop-local relay-to-child notice would be exact and is the alternative if the phone test shows false notices; it needs a PROTOCOL change and a design review first.

| Alternative | Why not now |
| --- | --- |
| Relay transcode for the weak child | Costs encoder time, latency and generation loss on the relay phone; last resort in the review |
| Spatial layers / simulcast (review P3) | Raises load on the first hop; a different, larger experiment |
| Source slows for the weakest child | Already the fan-out behaviour; violates the hop-local rule at a relay and hurts the other children |
| Always-on layering without the switch | The measured 2.5 VMAF cost stays opt-in |

**Phone tests and gates (not run).** Same gates for every phone; eligibility follows capabilities (a layered encoder or libaom; both relay and child decoders). One chain at a time; frozen APK; switch on every phone of a chain by tunable `relay_child_thinning`.

| Test | Setup | Pass when |
| --- | --- | --- |
| T-RT1 weak last hop | S24 -> ASUS -> A15s, GATT last hop (44-88 kbps), stream at 150-200 kbps and 15 FPS so the base layer (about 75-100 kbps) is at the link's edge; 5 min; switch on, then off on the same build | Off: the A15s at the old 0.1-0.2 FPS (control). On: the log shows the A15s at base (or audio when the link is below the base layer) within 10 s; the A15s presents about 7 FPS (half of 15) with no freeze loop and no withdrawal; ASUS own playback unchanged (FPS and frozen share within noise of off) |
| T-RT2 audio-only fallback | Same chain, a stream above what even the base layer needs (300 kbps, 30 FPS) | The A15s shows "Video paused: weak link", speech is continuous (audio drops no worse than off), and no keyframe request storm (at most the back-off schedule); when the last hop is made stronger the A15s returns to base/full within about 60 s with a keyframe |
| T-RT3 preservation, strong children | Chains where every child link is strong (S24 -> ASUS -> M31, CoC) and a direct S24 -> viewer | Level stays full for the whole run (`relay_child_layer` has only `full`), FPS, frozen share, latency and VMAF within noise of switch-off at equal bitrate except the declared layering cost (about 2.5 VMAF); no extra keyframe requests |
| T-RT4 two children at the source | One source, one strong and one weak direct child (the weak child is a relay's child in a second run) | The strong child is unaffected by the weak one's level changes |
| T-RT5 viewer states | A child at audio level; the source then pauses, turns the camera off, ends | "Video paused: weak link" never shows for a source pause or camera-off; the cover clears on video; the existing Recovering/Stream ended covers win |
| T-RT6 old build next to new | The previous APK as source, relay and child beside the new build with the switch off and on | Switch off changes nothing; with it on and an old source (no layers) the policy goes full -> audio rather than base |

Each T-RT reads `BENCHMARK relay_child_layer` (level, reason, queueAgeMs, deliveredKbps, offered and measured rates, thinned and paused counts, keyframe requests), the viewer's `weak_link_pause`, and the usual rendered-frame cadence; an offered-load check confirms the layered source's bitrate matches the requested one before any comparison.

**Change impact (inventory).** App behaviour changes only with the switch on. Touched stages: `MeshCore.kt` (`RelayChildQueue` levels, new queue results), `ForwardedStreamSecurity.kt` (`ReceiverNodeForwardingCore`), `ReceiverStreamForwarder.kt` (controller tick and log), `CameraVideoEncoder.kt` (layer request, `temporal_layering` log), `AndroidVideoReceiver.kt`/`MainActivity.kt` (pause notice), `BoundedMediaAge.kt` (classification moved to one shared function, behaviour unchanged), `DebugTunables.kt`. With the switch off the streaming cases keep their results; the shared classification and the new `ChildQueueOffer` values need the usual relay preservation run on the next frozen build. New cases for T-RT1..T-RT6 are generated through the suite inventory, not added to existing IDs.
